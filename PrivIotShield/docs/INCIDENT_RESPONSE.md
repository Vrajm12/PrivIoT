## 2. Step-by-Step Incident Investigation Procedure

### Step 1: Alert Detection & Notification
* Alert generated by deterministic detection engines (e.g. DGA entropy match, Threat Intel DNS indicator, or Behavioral Drift).
* Operator notified via SSE stream on `/dashboard` and `/alerts`.

### Step 2: Triage & Acknowledgment
* Analyst opens `/alerts/[id]` and clicks **Acknowledge**.
* Immutable audit event emitted recording operator ID and timestamp.

### Step 3: Forensic Evidence Review ("Why did this alert fire?")
* Inspect the 3-column forensic chain:
  - *Baseline Expected:* Approved local destinations and ports.
  - *Observed Flow:* Destination IP, port, and DNS hostname.
  - *Difference & PRI Impact:* Delta score and threat match attribution.

### Step 4: Containment Impact Preview
* Operator generates micro-segmentation rules for the target gateway (iptables, pfSense, UniFi).
* **Impact Analysis:** UI verifies that essential operational traffic (NTP `123`, DNS `53`, Gateway `10.10.1.1`, Camera `554`) is preserved while C2 egress is dropped.

### Step 5: Dual-Control Approval Gate
* System enforces `REQUIRE_APPROVAL` policy.
* User with role `APPROVER` or `ADMIN` authorizes policy application.

### Step 6: Enforcement & Active Verification
* Rules dispatched to gateway provider.
* Gateway confirms rule persistence and active packet drop counters.

### Step 7: Incident Resolution & Audit Attestation
* Analyst marks incident `RESOLVED`.
* Complete audit record preserved with full evidence payload.
